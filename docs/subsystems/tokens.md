# Token surface

Every `--cg-*` token family in `tokens.css`, what reads it, and the release that introduced it. Loaded from `.claude/rules/tokens.md` when you touch `tokens.css`, `base.css` or `index.css`.

Moved out of `CLAUDE.md` on 2026-10-31 by audit pass 6 (Docs). The text is verbatim from the sections it replaced, except where a line is marked *(rewritten 2026-10-31)* because the code no longer matched it.

---

Tokens live in `tokens.css` under `:root` (dark default) + `:root[data-theme="light"]` (light overrides).

- **Color:** `--cg-bg`, `--cg-bg-elevated`, `--cg-bg-surface`, `--cg-text`, `--cg-text-secondary`, `--cg-text-dim`, `--cg-text-muted`, `--cg-border`, `--cg-border-hover`, `--cg-border-subtle`, `--cg-accent`, `--cg-accent-dim`, `--cg-accent-glow`, `--cg-accent-subtle`, `--cg-backdrop`.
- **Status palette:** `--cg-status-success / warning / danger / blue / purple / neutral / archived / green / red / amber / cyan / magenta`. Consumed via `types/status.ts` maps in consumer repos.
- **Data-viz palette (Pulse charts):** `--cg-data-1..6` (categorical series colors — blue/orange/emerald/violet/magenta/gold, colorblind-aware), `--cg-data-reachable / -reachable-sms / -both / -unreachable` (fixed semantics for the audience opt-in ladder), `--cg-data-grid` + `--cg-data-track` (chart chrome). Re-pointed deeper in the light block so fills clear the ~3:1 non-text contrast floor on cream. Charts are ALSO themed per-module via an `accent` prop — these are the palette *independent* of module color. Spec: `cmngrdn/docs/_archive/pulse-analytics-design.md` *(path rewritten 2026-10-31)*.
- **Glass system:** `--cg-glass-bg`, `--cg-glass-bg-strong`, `--cg-glass-blur`, `--cg-glass-blur-strong`, `--cg-glass-border-top` (rim highlight, `var(--cg-text) 38%`), `--cg-glass-border-strong`, `--cg-glass-radius-sm/md/lg/pill`.
- **Fills:** `--cg-fill` / `--cg-fill-hover` / `--cg-fill-strong` — the tier BELOW glass (Apple's systemFill). A block that sits *inside* a surface: a row in a widget, a cell in a panel, a tile in a grid. Translucent by construction so the parent's glass still reads through, derived from `--cg-text` so they invert for free in light workspaces. **A fill is not a card — no border, no blur, no shadow.** See the surface-tier rule below.
- **Elevation:** `--cg-elev-0` through `--cg-elev-5` — five-tier shadow scale.
- **Typography classes:** `.cg-text-hero/display/title/body/small/label/label-sm/micro/mono/caption/callout`. Prefer these over inline `fontSize`/`fontWeight`.
- **Motion scale:** durations `--cg-duration-fast/base/slow/slower` (150/220/400/600ms) + easings `--cg-ease-entry` (decelerate, *appearing* surfaces), `--cg-ease-exit` (accelerate, *dismissing* surfaces), `--cg-ease` (bidirectional state changes), `--cg-ease-emphasize` (rare HIG featured motion). **JS-readable mirror: `cgos-ui/lib/motion`** — `duration`/`durationCss` (ms number + CSS string), `ease`/`easeCss` (cubic-bezier `[x1,y1,x2,y2]` tuple for framer + CSS string), `spring` (framer `transition` presets: gentle/bouncy/snappy), and a `cssTransition(props, {d,e,delayMs})` shorthand builder. Consume from here in any framer/rAF/`element.animate()` path so JS motion never drifts from the CSS tokens. Reduced-motion is a per-surface decision — gate at the callsite (CSS atoms do it in `base.css`).
- **Layer scale (`--cg-z-*`, v0.70.0):** `base 0 · raised 1 · sticky 100 · header 200 · overlay 1000 · backdrop 1100 · modal 1200 · popover 1250 · toast 1300 · tooltip 1400 · system 1500`. ⚠️ **1200 and 1300 are FIXED POINTS** — Modal and Toast shipped at them before the scale existed, in every consumer on every pin, so the scale is built AROUND them. **Popover sits ABOVE modal on purpose**: it used to be 1000 and a dropdown opened inside a modal drew behind it, which is why cmngrdn's calendar popover was at 3000 — and 3000 also cleared Toast, so a toast raised while a dropdown was open was invisible. One wrong number, both halves of the bug.
- **Control heights (`--cg-control-h-*`, v0.70.0):** `xs 24 · sm 32 · md 40 · lg 48`. Read by `Button` (`min-height`), `Select` (`height`) and `Input` (`height`). Before this the three sized themselves three different ways and `md` meant 44/40/40 — visible as mismatched controls in one form.
- ⚠️ **EVERY `var(--cg-*)` IN AN ATOM CARRIES ITS LITERAL AS A FALLBACK** — `var(--cg-control-h-md, 40px)`. An undefined custom property does not fall back to the previous value; it makes the whole declaration INVALID. Measured with a stale `tokens.css`: buttons 40px → 21px. And v0.70.0 shipped both scales *inside* the `[data-theme="light"]` block (appending stripped the file's last `}`, which belonged to that block) — the fallbacks are the only reason it was a patch release rather than an outage. **Verify a new token by reading `getComputedStyle(document.documentElement).getPropertyValue(...)` in a consumer, not by grepping the file.**
- **Touch hit area (`data-cg-hit`, v0.77.0):** any control that is not an atom opts into the atoms' 44px coarse-pointer hit box with one attribute (`="y"` for vertical-only). Measured need: every sub-44px control on a 390px phone in cmngrdn was a non-atom control.
- **Columns compress before they scroll (`ColumnHeader`, v0.77.0):** an unresized column is `minmax(floor, width)` — floor `compressTo`, else 60% — so a list beside an inspector tightens instead of hiding its last columns. A resized column keeps its exact width.
- **List tools: four drawers, one row (`ListToolbar`, v0.79.0):** search is a drawer opened by a square `SearchToggle` (accent at rest, filled while a query is on; `/` opens it, Esc keeps the query); Sort · Filter · Search · Pulse open one at a time and nothing opens on its own; the bar reads `Search · Filter · Sort ··· Pulse · View · +` and is ONE row at 375px; the count moved into the drawers. The gutter swaps at the page breakpoint (767px), not the row's width. Spec: `docs/subsystems/tools-row-contract.md` § 2026-09-28.
- **One colour per channel (v0.90.0, 2026-10-31):** `tokens.css` adds `--cg-channel-instagram` · `-facebook` · `-youtube` · `-google-business` (the `BRAND_META` hexes) and `--cg-channel-signals` (cyan), and moves `--cg-channel-email` from the Dispatch indigo to lavender `#a78bfa`, which sat beside Facebook blue. A glyph that names a channel wears its token.
- **The platform's help clause (v0.89.0, 2026-10-28):** `lib/legal.ts` exports `HELP_LINE` ("Reply HELP for help.", verbatim) and `buildPlatformHelpAndOptOut(entity)` — the many-Artists version of `buildHelpAndOptOut` for cmngrdn.com's `/terms` §11.3 and `/privacy`, which were hand-written. Both builders open with `HELP_LINE`; `buildHelpAndOptOut`'s output is byte-identical to v0.88.0.
- **One set of platform logos (v0.88.0, 2026-10-28):** `SocialBrandIcon` is the canonical platform mark — 31 Simple Icons (CC0) marks, `tone="mono"|"brand"`, `BRAND_META` + `brandInk()`; consumers stop keeping their own SVG switches and letter badges. Row: [atom-inventory](atom-inventory.md).
- **The HELP line every door's Terms carries (v0.87.0, 2026-10-28):** `buildHelpAndOptOut` now opens with the carrier-standard **"Reply HELP for help."** verbatim. Twilio's RCS review for AHLC flagged the Terms as missing it — the clause said the same thing in its own words ("Reply HELP to any message … for information"), and a reviewer reading for the phrase did not credit it. The contact beside it stays the entity's `supportEmail`, deliberately with no phone field. Same release: AHLC's `supportEmail` → `support@americanhorselabor.com`, Reliquary's → `contact@reliquaryarchives.com`, the inboxes their HELP auto-replies (Twilio console, Advanced Opt-Out) name — the Terms and the reply must agree. **One source, every door** (Blueprint v2 P11: shared clauses live in CGOS, each door's page in its repo): reliquary imports this module, AHLC regenerates from cmngrdn `/api/legal/clauses`, so a change here reaches a door only when that door is on this version.
- **The atoms on the scale (v0.86.0):** every atom's literal `font-size` now reads a UI role with its default as the fallback (`var(--cg-type-<role>-size, <default>px)`), so the kit's own text steps up on a phone with the rest of the page. Nine literals remain on purpose — Input/Select/Composer keep `16px` under the phone query (iOS zooms a field below 16px on focus), RcsCardPreview draws an Android card at its own sizes, plus one badge glyph and one display figure. `npm run audit:type` (CI) holds that ceiling.
- **Type and space (v0.85.0, Feather 2026-10-22):** the UI scale — seven text roles (`--cg-type-<role>-size|weight|lh|track`, classes `.cg-type-<role>`, plus `.cg-type-figure`), stepped up one on phone widths; the 4-point grid by number (`--cg-space-1…12`) and proximity gaps (`--cg-gap-inside|item|group`); density tokens `--cg-hit`/`--cg-row-min` that follow the POINTER (`pointer: coarse` → 44px). Spec: [`docs/subsystems/type-and-space.md`](type-and-space.md). Marketing `.cg-text-*` classes are a separate scale and unchanged.
- **Looks refit (v0.84.0, Feather 2026-10-22):** every `--cg-app-<id>` has a **Day value** in the light block (same hue, ≥ 4.5:1 as text on paper and under a white glyph — Knowledge's night bone measured 1.4:1 on a light world), mirrored as `APP_HEX_DAY`; `audit:apps` checks both blocks and measures the Day values. `ModuleIconChip variant="adaptive"` is translucent on a dark ground and solid with a white glyph on a light one. Hollow marks read `--cg-mark-hollow`/`--cg-mark-hollow-dim` (deeper in the light theme). `--cg-iris` gained its light value. **Flat:** `data-cg-flat` on the root turns the glass tokens opaque with no blur (Reduce Transparency; the consumer decides who sets it). `Window` draws a look's `--cg-glass-edge` as a hairline at its top.
- **Knowledge is an app (v0.83.0):** `knowledge` joins `APP_IDS` after `library`, colour **bone `#d8c9a3`** (`--cg-app-knowledge`; Feather, 2026-10-22), so its band, stub and record heads wear it (R5).
- **The band left to right (v0.82.0):** name · tabs · Setup (a gear tab) · Create · Adjust · Search after the tabs; Search's glyph widens into the field rightward and can run beside Adjust (`searchOpen`/`onSearchOpen`); the name leaves any mode. Feather, 2026-10-21.
- **`RecordWindowHead` `actions` + fixed rows (v0.81.0):** a record's own controls join expand/close in the head card's corner (a grid cell, so the title yields to any count); rows are fixed 21 · 19 · 17px. cmngrdn's whole record head is now this atom (Phase 3.5).
- **The window kit (v0.80.0):** `Window`/`WindowBand` (the band: name · tabs folding by measure · Search · Adjust · Create · Setup), `RecordWindowHead`, `Stub`, `Mark` (`Dot` · `TurnChip` · `StageMark` · `BookingDot`), `lib/apps` (`appColor` → `--cg-app-<id>`), and tokens for the marks' hues, the stage family and the window's geometry. Design authority is cgos `docs/hq-system.md`; the contract is `docs/subsystems/window-contract.md`. `GlassSurface` and `ModuleIconChip` moved their resting state to companion CSS in the same release.
- **`IconButton size="chip"` (v0.78.0):** the 28px bordered chip on the surface fill, for icon controls in a row of ControlChips — cmngrdn's inspector header had been forcing this look onto `size="sm"` with an inline `style`, which froze the background and killed hover. `ColumnEditCell` gained the vertical 44px touch box in the same release.
- **Chip step (`--cg-control-h-chip: 28px`, v0.71.0):** the height of a `ControlChip`, and of `Input`/`Select`/`Button` `size="chip"`. A NEW step between xs and sm — ⚠️ never redefine `--cg-control-h-xs` (24px, 53 cmngrdn call sites).
- **Chrome geometry (v0.71.0):** `--cg-chrome-h: 48px` (primary chrome rows — sidebar / page / inspector header), `--cg-chrome-subrow-h: 40px` (sub-tabs, filter strips, viewport toggles), `--cg-gutter: 24px` / `--cg-gutter-narrow: 12px` (the module inset — tab bar, tools row, shelves and rows all read it, or they cannot agree on an edge), `--cg-hairline` (`1px solid var(--cg-glass-border)` — CHROME dividers; content keeps `--cg-border`). Lifted from cmngrdn's local `--hq-chrome-height` / `--hq-chrome-subrow-height`, which remain until cmngrdn points them here. The gutter was a literal in ~41 places.
