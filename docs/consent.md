# Consent text — canonical source & surfaces

**One source of truth. Carrier-locked.** Every consent disclosure, opt-in
checkbox label, and SMS auto-reply shown to a fan — on any Common Garden
surface, in any repo — is generated by the builders in this package. No surface
ever hardcodes consent copy.

Why it matters: carrier reviewers (Twilio + T-Mobile / AT&T / Verizon / Google
RBM) routinely cross-check three things against each other — the consent UI on
the signup form, the public disclosure page, and the actual welcome SMS the
network delivered. If any two quote a slightly different version of the text,
the A2P 10DLC / RCS campaign gets bounced **for every artist on the platform**,
not just one.

## The two source files (must stay byte-identical)

| Runtime | File | Role |
|---|---|---|
| TypeScript | [`cgos-ui/lib/consent.ts`](../lib/consent.ts) | Canonical. All web surfaces import from here. |
| Python | `~/cgos/awen/legal/consent.py` | Hand-maintained **mirror**. The cgos backend can't import TS. |

`~/cgos/tests/test_consent_mirror.py` asserts the two produce identical strings
for identical args. **Editing any string is carrier-locked:** change *both*
files in the same PR and coordinate an A2P/RCS campaign resubmission.

## The args model — why it's "identical" without being "static"

Every builder takes `{ brandName, workspaceKind }` (TS) / `ConsentArgs(brand_name,
workspace_kind)` (Python). The structural CTIA elements (rate disclosure,
frequency clause, HELP/STOP, no-sharing, ordering, punctuation) are **locked in
the function body**; only the brand name and the message-types phrase vary.

The message-types phrase is resolved from `DEFAULT_MESSAGE_TYPES_BY_KIND`, e.g.
`artist → "new music releases, event announcements, and exclusive content"`.

So for a given workspace the rendered text is **identical on every surface**.
A `feather`/`artist` workspace produces the same string whether it's rendered on
`cmngrdn.com/feather/portal/<slug>`, `feather.fm/<slug>`, or recorded in the
consent ledger by the cgos backend. Drift is structurally impossible *as long as
every surface goes through the builders* — which is the rule below.

## Builders

| Builder | Used for |
|---|---|
| `buildMarketingEmailConsentText` | Marketing email opt-in checkbox label |
| `buildMarketingSmsConsentText` | Marketing SMS opt-in checkbox label |
| `buildConsentFinePrint` / `renderConsentFinePrintNodes` | The consolidated CTIA fine print rendered **once** below a form (rates / frequency / HELP-STOP, ending in linked Terms & Privacy) |
| `buildTransactional{Email,Sms}ConsentText` | Non-marketing (operational) opt-in labels — e.g. booking |
| `buildWelcome / Help / Stop / Start Message` | Twilio keyword auto-replies |
| `buildSmsConsentText` / `buildEmailConsentText` | Legacy single-surface strings (the `/sms` info page until migrated) |

## Surfaces (the authoritative consumer list)

Keep this current — when you add a surface that shows or records consent, add it
here and confirm it imports a builder.

**cmngrdn**
- `src/components/portal/CaptureForm.tsx` — marketing email + SMS labels + fine print
- `src/app/sms/page.tsx` — public disclosure page
- `src/components/hq/comms/CommsSettingsBody.tsx` — welcome-message preview

**feather.fm**
- `components/SignalConnectForm.tsx` — splash signup (marketing email + SMS + fine print)
- `components/PortalCaptureForm.tsx` — `/<slug>` portal capture
- `lib/contacts.ts` — **rebuilds** the text server-side for the consent ledger

**cgos backend** (Python mirror)
- `awen/routers/sms.py` — Twilio webhook auto-replies + welcome SMS

## Rules

1. **Never hardcode consent copy.** TS surfaces `import … from 'cgos-ui/lib/consent'`;
   Python surfaces `from legal.consent import …`.
2. **The consent *ledger* text is always rebuilt server-side** (feather
   `lib/contacts.ts`, cgos `legal/consent.py`) — never trusted from the client.
   Proof-of-consent must record what the canonical builder produces, stamped
   with `consent_version` (`cgos-ui@<pinned version>`).
3. **String edits are carrier-locked.** Change `lib/consent.ts` *and*
   `awen/legal/consent.py` together; the mirror test enforces parity; resubmit
   active A2P/RCS campaigns.
4. **New `workspace_kind`** → add its phrase to `DEFAULT_MESSAGE_TYPES_BY_KIND`
   in both files *and* the Supabase `workspaces.workspace_kind` CHECK migration.
